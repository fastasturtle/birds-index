# Журнал решений

Хронологический журнал решений по проекту и их контекста: чтобы будущие сессии и соавторы (в том числе орнитолог С. В. Волков, ЗММУ) видели, почему всё устроено именно так. Новые записи добавляются в конец.

## 2026-10-13

- **Скелет.** Берём AviList v2025b (CC BY 4.0), а не IOC и не Clements/eBird. Почему: IOC 15.2 — последний выпуск, дальше не обновляется; Clements/eBird распространяется по некоммерческой лицензии, и редистрибуция файла — серая зона. Объединять скелеты разных списков нельзя (разное деление видов приводит к дублям); объединять можно только источники русских названий поверх одного скелета.
- **Русские названия.** Каскад: IOC 15.2 (фактически список Волкова–Коблика ЗММУ на актуальной таксономии) → eBird (только добивка, не как файл) → Wikidata P1843 (CC0) → ручной слой `data/overrides.csv` (применяется последним, `ru_source=manual`). Поле `ru_source` хранится всегда, чтобы у каждого названия был виден источник.
- **Сопоставление.** Только по точному латинскому названию (с нормализацией регистра и пробелов). Почему: просто и предсказуемо, без ложных совпадений; умное сопоставление — issue #4.
- **Охват.** Только виды; подвиды — issue #2. Вымершие — только то, что помечено в AviList (после ~1500 г.); доисторические — issue #6.
- **Воспроизводимость.** Пайплайн запускается как `uv run scripts/build.py`; исходники AviList и IOC лежат в git (`data/raw`), eBird и Wikidata — в кэше (в .gitignore). CI данные не пересобирает (они меняются раз в год); сгенерированные файлы коммитятся. Ручные правки никогда не вносятся в сгенерированные файлы — только в `overrides.csv`, иначе они пропадут при пересборке.
- **Сайт.** Статика `docs/index.html` + `docs/data/*.json`, GitHub Pages из `docs/` при пуше в main, без сборщика и фреймворка. Почему: минимум зависимостей и обслуживания.
- **Процесс.** Работа в ветке → PR → мерж без ревью пользователя (так решил владелец). Дальнейшие задачи оформляются как GitHub issues, а не как TODO в чате.
- **Контекст: инициатива Волкова.** Инициатива исходит от С. В. Волкова (ЗММУ, соавтор «Птицы мира: рекомендуемые русские названия видов»). Это снимает вопрос лицензии на русскую колонку. У него нужно запросить: актуальный мастер-файл, позицию по AviList, русские названия для ~400 недавних сплитов, формулировку атрибуции. Слой `overrides.csv` — канал для его правок.
- **UX.** Решения приняты по итогам сравнения с IOC, Avibase, Birds of the World, xeno-canto, Степаняном, «Списком птиц РФ», Бёме–Флинтом: систематический порядок по умолчанию; заголовки отрядов и семейств внутри списка с русскими названиями; автор в стандартной записи «Linnaeus, 1758» прямым шрифтом в строке с курсивной латынью; порядок колонок латынь → русский → English; постоянная ссылка на вид `#<AvibaseID>` и состояние поиска в URL; на телефоне карточки, а не таблица; никакой информации только по наведению; блок «Как цитировать». Уровень 2 (указатели, карточка вида, синонимы, фильтры, экспорт, коды eBird) — issues #9–#14.
- **Названия отрядов и семейств.** Берутся предварительно из открытых источников (ЗММУ/Wikidata) до согласования с Волковым.
- **Отчёт сборки.** Дополнительно публикуется как документ Claude для чтения с телефона (ссылка в чате у владельца).
- **Источники названий отрядов и семейств.** В списке воробьиных ЗММУ (`Birds_rus_names_passerine.xlsx`) есть строки-заголовки семейств («Pittidae - Питтовые»), их и берём (`ru_source=zmmu`); каждый заголовок сверяется с семействами AviList у видов под ним, опечатки и расхождения в объёме семейств уходят в отчёт. В файле неворобьиных заголовков семейств нет, поэтому остальное (все отряды и неворобьиные семейства) добирается из Wikidata (P1843 или русская метка элемента). 7 названий внесены вручную через `overrides.csv` (в Wikidata нет или неудачное), 14 (5 отрядов, 9 семейств) оставлены пустыми — их должен дать Волков.
- **Нормализация авторов в пайплайне.** Поле `auth` («Linnaeus, 1758» вместо «Linnaeus, C, 1758») вычисляется в `build.py`, а не на странице: JSON самодостаточен для любых других потребителей (экспорт, приложения, Волков), исходное `authority` сохраняется рядом.
